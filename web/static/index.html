Model routing (optional)

Override which model each individual agent uses, and tune its generation parameters. Leave a field blank to inherit the primary or light default from above.

Model — which LLM this agent calls. Pick from the dropdown or leave blank to use the default. Max tokens (256–32768) — the maximum length of the agent's response. Higher values allow more detailed reasoning but cost more and take longer. Default varies per agent. Temperature (0.0–2.0) — controls randomness. 0.0 is deterministic (same input → same output), 0.7 is a good general-purpose default, 1.5+ is highly creative but may hallucinate. Use lower values for factual extraction (Grounder, Historian) and higher for creative synthesis (Theorist, Synthesizer).

Source API keys (optional)

Get a key from the source's developer portal (e.g. dev.elsevier.com for Scopus, core.ac.uk/services/api for CORE).

Excluded sources (optional)

    How SEEKER works

    A guide to the research pipeline, the agents that power it, and the breaks where you steer the process.

    Overview The pipeline Agents Breaks Artifacts Tips for best results

    Overview

    SEEKER is a multi-agent research assistant. You give it a research problem — not a keyword — and it maps the intellectual territory around that problem: where the field started, where it is now, what gaps remain, what approaches have been tried, what's feasible, and where to go next.

    The pipeline runs in fourteen steps: one pre-processing system step, ten agents, and three human-in-the-loop breaks. Each agent has a specific analytical role and produces structured output that feeds the next agent. The breaks are where you review the accumulated knowledge and steer the direction of the research.

    A completed run produces an Understanding Map — a citable document with intellectual genealogy, a reading curriculum, a conceptual map, and self-assessment questions. You can also request additional formatted outputs (blog posts, research briefs, paper sections, literature reviews) at Break 2.

    The pipeline

    The pipeline runs in a fixed order. Each step builds on everything that came before it:

    1. Concept Mapper (system) — expands your problem into themes
    2. Break 0 (human) — confirm or adjust the theme selection
    3. Grounder — excavates intellectual origins
    4. Social — discovers contemporary literature
    5. Historian — builds a chronological map
    6. Gaper — maps research gaps
    7. Break 1 (human) — validate ground truth
    8. Vision — extracts implications
    9. Theorist — proposes approaches
    10. Rude — evaluates feasibility
    11. Synthesizer — integrates everything into a narrative
    12. Break 2 (human) — evaluate the trajectory
    13. Thinker — opens new directions
    14. Scribe — formats outputs into artifacts

    The pipeline is divided into two halves by Break 1. Before the break, agents gather and map what is known. After the break, agents reason about what it means and where to go. This separation ensures that inferential agents (Vision, Theorist, Rude, Synthesizer) build on validated ground truth rather than unverified assumptions.

    Agents

    Each agent has a distinct analytical role. They are not general assistants — they are specialists that see specific inputs and produce specific outputs.

    Concept Mapper

    System step — runs before Break 0

    Translates your raw research problem into its full conceptual territory. Uses three layers: ConceptNet for semantic expansion, a curated disciplinary translation map, and an LLM pass to catch what the static map missed. The output is a list of themes that Social will use to find relevant literature. You confirm or adjust this list at Break 0.

    Grounder

    Agent — runs after Break 0

    Excavates the intellectual origins of your problem. Decomposes the problem into sub-questions, generates search queries, and queries academic databases (OpenAlex, Semantic Scholar, Consensus, Google Books, Open Library) plus web search. Produces seminal works with intellectual genealogy, fundamental motivations, and original definitions. Creates the argument tree root — the structural backbone that all subsequent agents extend.

    Social

    Agent — runs after Grounder

    Discovers contemporary literature across academic sources (OpenAlex, arXiv, PubMed, Semantic Scholar, CrossRef, JSTOR, PhilPapers, SSRN, CORE, BASE, HAL). Uses the themes from Concept Mapper to search broadly across disciplines. Saves sources as "current" and extends the argument tree with current evidence nodes. Non-fatal if it fails — the pipeline continues with what Grounder found.

    Historian

    Agent — runs after Social

    Builds a chronological map from Grounder's seminal works. Tracks phases, turning points, dead ends, key actors, and how methods evolved over time. Audits the argument tree for claim solidity (well-supported, contested, weak, unsupported) and adds audit notes. Produces historical works with phase tags and extends the tree with historical and external factor nodes.

    Gaper

    Agent — runs after Historian

    Maps research gaps using a three-step process. First, it finds structural gaps from the argument tree (unanswered questions, unsupported claims, weak claims) — these are proven gaps the tree structure proves exist. Second, it finds analytical gaps via LLM scan (disciplinary silences, methodological blind spots, assumption gaps, dead-end revisit opportunities). Third, it merges both into a single gap map with significance ratings and references to all three source layers.

    Vision

    Agent — runs after Break 1

    Extracts logical consequences and implications from the accumulated knowledge. The first inferential agent — it doesn't gather information, it reasons about what the information means. Produces direct implications, logical chains, second-order consequences, hidden assumptions, gap demands (what must be true for a gap to matter), and logical contradictions. Rates each implication by strength: Strong, Moderate, or Speculative.

    Theorist

    Agent — runs after Vision

    Proposes concrete approaches, frameworks, and solutions anchored in the pipeline outputs. Uses a two-pass design: pass 1 produces an overview and index, pass 2 expands each proposal with full detail. Produces 4–8 proposals with types (novel, extension, revival, hybrid), promise ratings, assumptions, requirements, and predictions. Each proposal is grounded in the foundations, timeline, gaps, and implications from earlier agents.

    Rude

    Agent — runs after Theorist

    Evaluates Theorist's proposals strictly on empirical evidence. Cross-references each proposal against historical dead ends and current intelligence to check whether it's actually feasible. Produces feasibility verdicts: feasible, partially feasible, unfeasible, or insufficient evidence. For each verdict, it identifies the weakest empirical links and what evidence would be needed to change the verdict. This is the agent that keeps the Theorist honest.

    Synthesizer

    Agent — runs after Rude

    Integrates all pipeline outputs into a single coherent research narrative. Not a summary — an organizing intelligence that builds an argument. Produces a sharpened problem statement, a knowledge landscape (what's known, what's contested, what's unknown), a gap landscape summary, viable proposals ranked by feasibility, and a trajectory statement. Flags tensions, contradictions, and any Break 1 overrides you applied.

    Thinker

    Agent — runs after Break 2

    Opens new directions from the synthesis. The first agent explicitly allowed to look beyond the current frame — but from a position of deep knowledge, not ignorance. Identifies new research directions, alternative framings, adjacent fields, second-generation questions, underexplored combinations, and challenges to unchallenged assumptions. Rates each direction by distance: Near (buildable now), Mid (needs development), or Far (speculative but generative).

    Scribe

    Agent — runs last

    Formats pipeline outputs into audience-ready artifacts. The Understanding Map is a mandatory output for every run — it includes coverage metrics, intellectual genealogy, a tiered reading curriculum, a conceptual map, an unresolved core question, and self-assessment questions with citation keys validated against retrieved sources. Scribe can also produce blog posts, research briefs, internal memos, paper sections, literature reviews, and grant backgrounds in .md or .tex format, requested at Break 2.

    Breaks

    Breaks are hard stops where the pipeline parks and waits for your input. At each break, the system generates a structured review document summarizing what the agents have found so far. You review it and provide instructions using specific directives. The run resumes automatically after you submit your response.

    At any break you can also:

    • Change models — switch any agent to a different LLM for the rest of the run
    • Skip sources — disable a problematic source (e.g. one that's rate-limiting you)
    • Add free-form directives — natural language instructions appended to the next agent's context

    Break 0 — Theme Confirmation

    After Concept Mapper, before Grounder

    The Concept Mapper has expanded your problem into themes. Review the selection — are these the right themes to search? You can:

    • CONFIRMED — accept the selection as-is
    • ADD THEME: <theme_id> — include a theme that was excluded
    • REMOVE THEME: <theme_id> — drop a theme that was selected

    This is your chance to catch conceptual mismatches early. If the themes don't match your understanding of the problem, adjust them here — it's much cheaper than correcting downstream.

    Break 1 — Ground Truth Validation

    After Gaper, before Vision

    The gathering phase is complete. Grounder, Social, Historian, and Gaper have mapped the territory. Review their findings — are the gaps real? Are the seminal works correct? You can:

    • CONFIRMED — everything is correct
    • CORRECT GAP <gap_id>: <text> — revise a gap's description
    • REMOVE GAP <gap_id> — drop a gap that isn't actually a gap
    • ADD GAP: <description> — add a gap the agents missed
    • OVERRIDE SEMINAL <source_id>: <note> — correct a seminal assessment

    This is the most important break. Everything after it — Vision, Theorist, Rude, Synthesizer — reasons on top of what you validate here. If the ground truth is wrong, the reasoning will be wrong too. Take the time to get this right.

    Break 2 — Trajectory Evaluation

    After Synthesizer, before Thinker

    The Synthesizer has produced a research narrative with proposals ranked by feasibility. Review the trajectory — do you agree with the verdicts? Do you want specific outputs formatted? You can:

    • CONFIRMED — accept the trajectory
    • OVERRIDE VERDICT <evaluation_id>: <reasoning> — disagree with a feasibility verdict
    • SCRIBE OUTPUT: <type> | audience: <audience> — request a formatted artifact

    Available output types: blog_post, research_brief, internal_memo, paper_section, literature_review, grant_background. The audience parameter tailors the tone and depth (e.g. "specialists in cognitive science", "program officers at NSF", "a general academic audience").

    Artifacts

    A completed run produces several artifacts, all accessible from the run's Artifacts tab:

    • Understanding Map — the core deliverable. Coverage metrics, intellectual genealogy, a tiered reading curriculum, a conceptual map, an unresolved core question, and self-assessment questions. Generated for every run.
    • Historical map — chronological phases, turning points, and methods evolution from Historian
    • Implications map — logical consequences and inferential chains from Vision
    • Proposals — concrete approaches with promise ratings from Theorist
    • Feasibility report — empirical evaluations of proposals from Rude
    • Research narrative — integrated synthesis with sharpened problem and trajectory from Synthesizer
    • New directions — research openings with distance ratings from Thinker
    • Break reviews — the structured review documents generated at each break
    • Requested outputs — any blog posts, briefs, paper sections, etc. requested at Break 2

    The argument tree (visible in the Tree tab) is the structural backbone — every claim, question, evidence node, and gap that the agents added throughout the run. It's the connective tissue between all the artifacts.

    Tips for best results

    • State a problem, not a keyword. "How does identity influence intelligence through the lens of identity theory?" is a problem. "identity intelligence" is a keyword. The pipeline maps territory around problems; keywords produce shallow results.
    • Take Break 1 seriously. It's the single most influential point in the pipeline. If you skip it with a quick CONFIRMED, downstream agents reason on unvalidated ground truth. Read the gap analysis and seminal works carefully.
    • Use the model routing wisely. Factual agents (Grounder, Historian) benefit from lower temperature (0.3–0.5) for precise extraction. Creative agents (Theorist, Synthesizer) benefit from higher temperature (0.8–1.2) for generative reasoning. The defaults are sensible but not optimal for every domain.
    • Add API keys for sources. Sources without keys are silently skipped. If your field relies on Scopus, CORE, or Semantic Scholar, add keys in the Source API keys section or your .env file to get full coverage.
    • Use the compare-to-previous-run feature. If you've run on the same topic before, selecting the previous run flags already-seen sources so you can focus on what's new.
    • Request outputs at Break 2. The Understanding Map is always produced, but if you need a formatted artifact (blog post, paper section, literature review), you must request it at Break 2 using the SCRIBE OUTPUT directive.
    • Skip sources that are failing. If a source is rate-limiting or returning errors, use the skip button on the Sources tab to disable it mid-run. This won't interrupt in-flight calls but prevents future ones.
    • Let the pipeline run fully. Each agent builds on the previous ones. If you cancel mid-run, you get partial results — useful for debugging, but not for research. Let it complete to get the full picture.
