Override which model each individual agent uses, and tune its generation parameters. Leave a field blank to inherit the primary or light default from above.

Model — which LLM this agent calls. Pick from the dropdown or leave blank to use the default. Max tokens (256–32768) — the maximum length of the agent's response. Higher values allow more detailed reasoning but cost more and take longer. Default varies per agent. Temperature (0.0–2.0) — controls randomness. 0.0 is deterministic (same input → same output), 0.7 is a good general-purpose default, 1.5+ is highly creative but may hallucinate. Use lower values for factual extraction (Grounder, Historian) and higher for creative synthesis (Theorist, Synthesizer).

You can change all of these mid-run at any break point.

Source API keys (optional)

Compare to previous run (optional)

Select a previous run to compare against. Sources already found in that run are flagged as "previously seen" in the Understanding Map, so you can see what's new since your last pass at this topic. Useful for tracking how the literature evolves between runs, or for resuming a broad survey without re-reading the same papers. Leave as "None" for a fresh start.

Excluded sources (optional)

Sources you mark here are never inserted into your runs — useful for retracted papers, predatory journals, or authors whose work you don't want cited. Matches are case-insensitive and work by: DOI (exact, e.g. 10.1234/abc), URL (substring, e.g. predatory-journal.com), or title substring (e.g. "predatory journal"). Exclusions persist across all your future runs until removed.

    Quick start

    SEEKER is a multi-agent research assistant. You give it a research problem — not a keyword — and a pipeline of specialist agents maps the intellectual territory around it: where the field started, where it is now, what gaps remain, what approaches are feasible, and where to go next. Your first run takes five steps:

    1. Connect a model provider. Go to Settings → Providers and add an API key for your LLM provider. Pick a primary model (heavy reasoning) and a light model (summarizing and formatting). Nothing can run without this.
    2. Optionally add source API keys. Settings → Source keys holds keys for academic databases that need them (Scopus, CORE, Semantic Scholar, …). Sources without a required key are silently skipped — the run still works, with narrower coverage.
    3. Start a run. Click New run and state your problem as a question or claim, for example: "How does identity influence intelligence through the lens of identity theory?" Everything else on the form is optional. A cost/duration estimate appears before you commit.
    4. Respond at the three breaks. The pipeline pauses three times and waits — as long as it takes — for your review: theme selection (Break 0), ground-truth validation (Break 1), and trajectory evaluation (Break 2). A "your turn" banner appears on the run page each time.
    5. Collect your results. The Artifacts tab holds the Understanding Map, any outputs you requested at Break 2, and a combined HTML report you can save as a PDF.
    What to expect: agent steps typically take a few minutes each, depending on your models and how many sources you query. The Overview tab shows a live ETA once a couple of steps have finished. Breaks don't expire — you can respond hours or days later and the run resumes exactly where it paused.

    How a run works

    Every run walks the same sixteen steps in a fixed order — twelve automated steps, three human breaks, and one pre-processing step. They fall into four phases:

    Phase 1 — Scope (steps 1–2)

    1. system Concept Mapper — expands your problem into searchable themes
    2. you Break 0 — confirm or adjust the theme selection

    Phase 2 — Gather (steps 3–8)

    1. agent Grounder — excavates the intellectual origins
    2. agent Social — discovers contemporary literature
    3. agent Historian — builds the chronological map
    4. agent Gaper — maps the research gaps
    5. agent Librarian — checks your library catalog for each source
    6. you Break 1 — validate the ground truth

    Phase 3 — Reason (steps 9–13)

    1. agent Vision — extracts implications and consequences
    2. agent Theorist — proposes concrete approaches
    3. agent Rude — evaluates their feasibility on the evidence
    4. agent Synthesizer — integrates everything into a narrative
    5. you Break 2 — evaluate the trajectory, request outputs

    Phase 4 — Deliver (steps 14–16)

    1. agent Thinker — opens new research directions
    2. agent Scribe — writes the Understanding Map and requested outputs
    3. agent Reporter — assembles the combined HTML report

    Break 1 divides the pipeline in half. Before it, agents gather and map what is known; after it, agents reason about what it means. That's why Break 1 matters most: everything downstream builds on what you validate there.

    If Social fails (a source outage, say), the run continues with what Grounder found — it is the one deliberately non-fatal step. Any other failed step stops the run and offers a retry.

    Starting a run

    The research problem

    The only required field. State a problem, not a keyword — "How does identity influence intelligence through the lens of identity theory?" is a problem; "identity intelligence" is a keyword. The pipeline maps territory around problems; keywords produce shallow results.

    Provider and models

    Choose which provider the run bills against and which models fill the two roles: primary (heavy reasoning agents) and light (Social and Scribe). Your choices are saved against the provider and pre-filled next time.

    Model routing (optional)

    Override the model, max tokens (256–32768), and temperature (0.0–2.0) per agent. Lower temperature (0.3–0.5) suits factual extraction (Grounder, Historian); higher (0.8–1.2) suits generative reasoning (Theorist, Synthesizer). All of this can also be changed mid-run at any break.

    Sources (optional)

    Pick which academic databases the run queries — OpenAlex, arXiv, PubMed, Semantic Scholar, CORE, PhilPapers, and more. Sources that need an API key you haven't provided are skipped at run time. The results per source limit (default 8) directly drives run cost and duration.

    Templates, comparison, and exclusions (optional)

    • Templates — the bar at the top of the form saves and restores a tuned set of model and source choices, so a configuration you like is one click away next run.
    • Compare to previous run — pick an earlier run on the same topic and sources already seen there are flagged as "previously seen" in the Understanding Map, so you can focus on what's new.
    • Excluded sources — block specific works by DOI, URL, or title substring (retracted papers, predatory journals). Exclusions persist across all your future runs.
    Before you commit: an estimate card appears above the Start button showing the expected scale of the run — treat it as a rough guide, not a quote.

    Following a run

    The run list shows every run with its status. Use the search box and status chips (Running, Awaiting break, Complete, Failed, Stopped) to find a run; the list updates live. Opening a run shows four tabs, plus a Break tab whenever the pipeline is waiting on you:

    • Overview — the live step list. The card at the top shows what's happening right now: the running agent, its elapsed time and current activity, an ETA once enough steps have finished, and per-source progress while Grounder and Social are querying databases.
    • Sources — every work the agents have gathered, with links out to the original. If a database is misbehaving mid-run (rate limits, errors), skip it here — future calls stop, in-flight ones finish.
    • Tree — the argument tree: every question, claim, evidence node, and gap the agents added, as a collapsible hierarchy. Use the filter bar to search the tree's text or narrow it by node type or status; matches are highlighted and their ancestors kept for context.
    • Artifacts — the finished documents (see Your results).

    Stopping, failures, and retries

    • Stop and change model — available while an agent runs. The in-flight step is discarded so it can restart cleanly; the usual reason to stop is switching a struggling model, and the stopped screen lets you do exactly that before resuming.
    • Failed step — the run halts and shows the error with a Retry this step button. If the failure came from the LLM (rate limit, context overflow), change the agent's model first, then retry. No completed work is lost.

    Breaks — where you steer

    A break is a hard stop: the pipeline parks and nothing runs until you respond. Each break presents a structured review document summarizing what the agents found, and a response box. You steer with one-per-line directives — every ID a directive needs (theme_id, gap_id, source_id, evaluation_id) is printed in the review document next to the item it names. Anything you write that isn't a directive is passed to the downstream agents as free-form guidance.

    At any break you can also switch any agent's model for the rest of the run, and enable or disable sources — both from panels below the response box.

    Break 0 — Theme confirmation

    After Concept Mapper · before Grounder

    The Concept Mapper has expanded your problem into themes and selected the ones it will search. Catching a conceptual mismatch here is far cheaper than correcting it downstream.

    • CONFIRMED — accept the selection as-is
    • ADD THEME: <theme_id> — include an excluded theme
    • REMOVE THEME: <theme_id> — drop a selected theme
    Example response — steering the theme selection
    ADD THEME: social_identity_theory
REMOVE THEME: artificial_intelligence
Focus on human cognition — "intelligence" here means cognitive ability, not AI.

    Break 1 — Ground truth validation

    After Librarian · before Vision

    The gathering phase is done: seminal works, contemporary literature, the historical map, and the gap analysis are all in, and the Librarian has attached library catalog records and availability where it found them. This is the most important break. Every reasoning agent after it builds on what you validate here — read the gaps and seminal works carefully, follow the DOI/URL backlinks, and correct anything wrong.

    • CONFIRMED — everything is correct
    • CORRECT GAP <gap_id>: <text> — revise a gap's description
    • REMOVE GAP <gap_id> — drop a gap that isn't one
    • ADD GAP: <description> — add a gap the agents missed
    • OVERRIDE SEMINAL <source_id>: <note> — correct a seminal-work assessment
    Example response — correcting the ground truth
    CORRECT GAP gap_3: The missing piece is cross-cultural replication, not longitudinal design.
REMOVE GAP gap_7
OVERRIDE SEMINAL src_12: This is a later survey, not the origin — the 1979 Tajfel & Turner chapter is.
ADD GAP: No work connects identity threat to test performance outside laboratory settings.

    Break 2 — Trajectory evaluation

    After Synthesizer · before Thinker

    The Synthesizer has produced a research narrative with proposals ranked by feasibility. Review the verdicts, and — importantly — request any formatted outputs you want, because this is the only point where Scribe takes orders.

    • CONFIRMED — accept the trajectory
    • OVERRIDE VERDICT <evaluation_id>: <reasoning> — disagree with a feasibility verdict
    • SCRIBE OUTPUT: <type> | audience: <audience> — request a formatted artifact

    Output types: blog_post, research_brief, internal_memo (markdown); literature_review, paper_section, grant_background (LaTeX). The audience phrase tailors tone and depth. If you request nothing, you still get a research brief alongside the Understanding Map.

    Example response — accepting and ordering outputs
    CONFIRMED
SCRIBE OUTPUT: literature_review | audience: specialists in social psychology
SCRIBE OUTPUT: blog_post | audience: a general academic audience

    Agent reference

    Each agent is a specialist with a fixed role — it sees specific inputs and produces specific outputs that feed the next step.

    Concept Mapper · system step

    Translates your problem into its full conceptual territory using three layers: ConceptNet semantic expansion, a curated disciplinary translation map, and an LLM pass to catch what the static layers missed. Its themes drive Social's cross-disciplinary search; you vet them at Break 0.

    Grounder

    Excavates the intellectual origins of your problem. Decomposes it into sub-questions, queries academic databases and web search, and produces seminal works with genealogy, motivations, and original definitions. Creates the argument tree root that every later agent extends.

    Social

    Discovers contemporary literature across the academic sources you enabled, searching broadly along the Break-0 themes. Saves "current" sources and adds current-evidence nodes to the tree. Non-fatal: if it fails, the run continues on Grounder's findings.

    Historian

    Builds a chronological map from the seminal works — phases, turning points, dead ends, key actors, and how methods evolved. Audits the argument tree for claim solidity (well-supported, contested, weak, unsupported).

    Gaper

    Maps research gaps in three passes: structural gaps the argument tree proves exist (unanswered questions, unsupported claims), analytical gaps from an LLM scan (disciplinary silences, methodological blind spots, assumptions, dead ends worth revisiting), then a merged gap map with significance ratings. You vet this map at Break 1.

    Librarian

    Searches your institution's library catalog (Ex Libris Primo) for every gathered source and attaches catalog links, availability, and ISBN/ISSN — so at Break 1 you can see which works you can actually get your hands on. Deterministic, no LLM calls. If Primo isn't configured (Settings → MCP connections), the step passes gracefully and the run continues without catalog data.

    Vision

    The first inferential agent — it reasons about what the gathered knowledge means. Produces implications, logical chains, second-order consequences, hidden assumptions, and contradictions, each rated Strong, Moderate, or Speculative.

    Theorist

    Proposes 4–8 concrete approaches anchored in the foundations, timeline, gaps, and implications — typed (novel, extension, revival, hybrid) with promise ratings, assumptions, requirements, and predictions.

    Rude

    Stress-tests the Theorist's proposals strictly on empirical evidence, cross-referencing historical dead ends. Verdicts: feasible, partially feasible, unfeasible, or insufficient evidence — each naming the weakest empirical link and what evidence would change the verdict. You can override any verdict at Break 2.

    Synthesizer

    Integrates everything into one research narrative: a sharpened problem statement, the knowledge landscape (known / contested / unknown), the gap landscape, proposals ranked by feasibility, and a trajectory statement. Flags tensions and any Break-1 overrides you applied.

    Thinker

    Opens new directions from the synthesis — the first agent allowed to look beyond the current frame, from a position of knowledge rather than ignorance. Each direction is rated by distance: Near (buildable now), Mid (needs development), Far (speculative but generative).

    Scribe

    Writes the deliverables. The Understanding Map is produced on every run; each SCRIBE OUTPUT you requested at Break 2 becomes an additional artifact in markdown or LaTeX, with citations validated against the retrieved sources.

    Reporter

    The final step. Assembles everything into a single self-contained HTML report: cover page, table of contents, charts of source coverage, gap significance, proposal verdicts and publication timeline, an executive summary, and every Scribe artifact as its own section. Print-styled, so saving it to PDF from your browser gives you the whole run as one document.

    Your results

    A completed run leaves you three kinds of output:

    • The Artifacts tab — the Understanding Map (every run): coverage metrics, intellectual genealogy, a tiered reading curriculum, a conceptual map, the unresolved core question, and self-assessment questions with validated citations. Plus any outputs you requested at Break 2, and the combined report — the Reporter's single HTML document covering the whole run, ready to save as PDF.
    • The Tree tab — the argument tree, the structural backbone connecting every claim, question, evidence node, and gap. It stays browsable and filterable after the run finishes.
    • The break reviews — the structured documents generated at each break (historical map, gap analysis, implications, proposals, feasibility verdicts, the synthesis narrative) remain readable from the run's break panels, so the intermediate analysis is never lost.

    Settings & customization

    Everything under Settings is scoped to your account — your credentials and preferences are private and follow you across browsers.

    • Profile — your account details.
    • Providers — LLM provider credentials and the primary/light model choices runs are pre-filled from. Required before your first run.
    • Source keys — API keys for academic databases that need them. Stored encrypted; used in place of the matching server-side .env variable for your runs.
    • MCP connections — external tool connections: Consensus (evidence search) and Primo (your library catalog, which powers the Librarian step). Toggle each on or off for your runs.
    • Preferences — run defaults (provider, models, sources, template, results per source) so the New Run form pre-fills itself; appearance (theme, density, font scale); display options (runs per page, sort order, default run tab, timestamp format); and notification choices for break-ready, completion, and failure alerts.

    Tips & troubleshooting

    • Take Break 1 seriously. It is the single most influential point in the pipeline. A reflexive CONFIRMED means every downstream agent reasons on unvalidated ground truth.
    • Tune temperature per agent. Factual agents (Grounder, Historian) do better at 0.3–0.5; generative agents (Theorist, Synthesizer) at 0.8–1.2. The defaults are sensible but not optimal for every domain.
    • Add source keys for your field. If your literature lives in Scopus, CORE, or Semantic Scholar, add keys under Settings → Source keys — sources without required keys are skipped silently.
    • Re-running a topic? Use compare. Selecting a previous run flags already-seen sources so the Understanding Map shows you what's new.
    • A source is failing mid-run? Skip it from the Sources tab — future calls stop immediately — or disable it for the rest of the run at the next break.
    • An agent step failed? Open Overview: the error is shown with a Retry this step button. For LLM errors (rate limits, context overflow), switch that agent's model first, then retry.
    • Wrong model mid-run? Use Stop and change model on the Overview tab. The in-flight step is discarded and re-run cleanly with the new routing.
    • Save what works. When a model/source configuration serves you well, save it as a template from the New Run form and reuse it in one click.
    • Let runs finish. Each agent builds on the previous ones; a cancelled run yields partial results that are useful for debugging, not research.
